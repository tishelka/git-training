# Если Git ругается: что делать?

Во-первых, сообщение об ошибке — не катастрофа. Git обычно честно объясняет, что ему не понравилось. Начните с `git status` и прочитайте последние строки ошибки.

## «git: command not found» или «git не является командой»

Git не установлен или терминал пока его не видит. Установите [Git](https://git-scm.com/downloads) и полностью перезапустите VS Code.

## «Please tell me who you are»

Git не знает, чьим именем подписывать коммиты:

```bash
git config --global user.name "Ваш ник"
git config --global user.email "ваша-почта@example.com"
```

## «Permission denied» или «403» при push

Чаще всего у вас нет права записи или вы авторизовались не под тем аккаунтом. Проверьте, что приняли приглашение Collaborator. **Не отправляйте руководителю пароль и токены.** Если права записи нет, спросите про приглашение или работу через fork.

## «Authentication failed»

GitHub не принимает пароль аккаунта как пароль Git для HTTPS. Используйте браузерную авторизацию через Git Credential Manager. Если авторизация сломалась, обратитесь за помощью — не вставляйте токены в сообщения и не коммитьте их.

## «src refspec main does not match any»

В нашем учебном репозитории основная ветка — **master**, а не `main`. Проверьте название командой:

```bash
git branch --show-current
```

## «fatal: not a git repository»

Вы находитесь не в папке репозитория. Проверьте текущую директорию (`pwd` в большинстве терминалов; `Get-Location` в PowerShell) и перейдите в `git-training`.

## «nothing to commit, working tree clean»

Это не ошибка: Git не видит новых изменений. Проверьте, сохранили ли файл, создали ли его внутри нужной папки и не был ли он уже закоммичен.

## «Your local changes would be overwritten»

У вас есть незакоммиченные правки, а Git не хочет их потерять. Посмотрите `git status`. Если правки нужны, сохраните их коммитом в своей ветке. Не запускайте `reset --hard`.

## «non-fast-forward» или «rejected» при push

В удалённой ветке уже есть коммиты, которых нет локально. Для начала:

```bash
git status
git fetch origin
```

Дальше решение зависит от того, чьи изменения находятся в этой ветке. Не используйте `git push --force`, особенно в общей ветке; лучше покажите вывод руководителю.

## В файле появились <<<<<<< и =======

Это метки конфликта. Git просит выбрать итоговый текст. Читайте [задание 3](../exercises/03-merge-conflict.md). Удалите метки после выбора текста, затем `git add` и `git commit`.

## Я не вижу кнопку Create pull request

Проверьте, отправили ли **ветку** командой `git push -u origin имя-ветки`. Затем откройте **Pull requests → New pull request**, выберите base `master` и compare — свою ветку.

## Я случайно добавил лишний файл в git add

```bash
git restore --staged путь/к/файлу
```

Правки останутся на диске, просто не попадут в ближайший коммит.

---

Если проблему не удалось решить, пришлите руководителю **текст ошибки, выполненную команду и вывод `git status`**. Не присылайте секретные токены, пароли и приватные файлы.
