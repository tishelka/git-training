# Задание 3. Конфликт — не катастрофа

**Цель:** узнать, что делать, когда двое поменяли одну и ту же строку. Это обычная ситуация в командном проекте.

Для упражнения нужен **напарник** и согласование с руководителем. Не работайте над конфликтом в `master`.

## Подготовка

Оба студента сначала получают свежую версию:

```bash
git switch master
git pull --ff-only origin master
```

У каждого должна быть отдельная ветка:
- первый: `practice/anna-conflict`;
- второй: `practice/max-conflict`.

Оба изменяют **одну и ту же строку** в файле [team-message.md](../practice/team-message.md), но пишут разные тексты, например разные варианты девиза команды.

Оба создают коммиты и отправляют ветки.

## Что произойдёт дальше

Руководитель сначала принимает PR первого студента. Теперь в `master` строка изменилась, а во второй ветке осталась другая версия — Git не всегда сможет автоматически выбрать между ними.

Второй студент выполняет:

```bash
git switch practice/max-conflict
git fetch origin
git merge origin/master
```

Если Git сообщил о конфликте, откройте `practice/team-message.md`. Там могут появиться такие метки:

```text
<<<<<<< HEAD
Мой вариант строки
=======
Вариант из master
>>>>>>> origin/master
```

**Это не ошибка файла и не текст для коммита.** Выберите одну формулировку или соберите новую, удалите все строки-маркеры (`<<<<<<<`, `=======`, `>>>>>>>`), сохраните файл.

Потом:

```bash
git status
git add practice/team-message.md
git commit
git push
```

После `git commit` Git может открыть редактор сообщения merge-коммита — сохраните сообщение и закройте редактор.

Если конфликт получился слишком запутанным, можно отменить *только текущую попытку слияния* командой `git merge --abort` и обратиться за помощью.

## Что запомнить

- Конфликт не означает, что работа потерялась.
- Не нужно сразу использовать `--force`, удалять ветку или сбрасывать всё `reset --hard`.
- Перед коммитом убедитесь, что маркеры конфликта удалены.
- Конфликт бывает не всегда: если вы меняете разные строки, Git обычно объединит их автоматически.
