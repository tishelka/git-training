# Задание 2. Обновления и замечания

**Цель:** привыкнуть к реальной командной работе. PR редко принимают без единого комментария — и это нормально.

## Часть А. Исправьте свой PR

Пока PR первого задания ещё открыт, руководитель может попросить добавить строку «Чему хочу научиться» или уточнить формулировку.

1. Откройте **свою** ветку (`git branch --show-current`).
2. Измените файл `students/yourname.md`.
3. Выполните:

```bash
git add students/yourname.md
git commit -m "Improve profile after review"
git push
```

Откройте прежний PR: новый коммит уже в нём! Не создавайте ещё один PR ради ответа на замечание.

Если первый PR уже принят, пропустите часть А и выполняйте следующую в новой ветке.

## Часть Б. Получите свежий общий проект

Когда PR принят, вернитесь на `master` и заберите изменения команды:

```bash
git switch master
git pull --ff-only origin master
git log --oneline -5
```

Теперь создайте **новую** ветку:

```bash
git switch -c practice/yourname-update
```

В своём файле `students/yourname.md` добавьте короткий раздел **«Что я понял про Git»** — 2–3 предложения своими словами.

Сделайте коммит, отправьте ветку и создайте второй PR.

## Что проверить

- [ ] Перед новой задачей я обновил `master`.
- [ ] Второе изменение сделано в **новой** ветке.
- [ ] В PR нет случайных правок других файлов.
- [ ] Я понимаю, что `git pull` не заменяет `git push`.

**Вопрос на подумать:** почему не стоит продолжать все задачи в одной старой ветке? Подсказка: тогда в новом PR легко окажутся изменения из предыдущих заданий.
