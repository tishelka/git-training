# Git без паники: учебная площадка команды «ЧтоДальше» 🚀

Привет! Здесь мы будем разбираться с Git и GitHub не по лекциям на сто слайдов, а на практике. Вы скачаете этот репозиторий, сделаете небольшое изменение, отправите его на GitHub и оформите **Pull Request** — точно так же потом будем работать над приложением «ЧтоДальше».

**Git впервые? Это нормально.** Не нужно запоминать все команды сразу. Шпаргалка лежит рядом, а в заданиях написано, что делать и зачем.

> Тут можно ошибаться. Репозиторий тренировочный: лучше впервые увидеть конфликт или неудачный коммит здесь, чем в рабочем проекте.

## С чего начать

Понадобятся:
- [Git](https://git-scm.com/downloads) — программа, которая следит за изменениями файлов;
- [VS Code](https://code.visualstudio.com/) — редактор, в котором будем менять файлы и открывать терминал;
- [аккаунт GitHub](https://github.com/) — место, куда будем отправлять работу.

После установки откройте терминал в VS Code (**Терминал → Создать терминал**) и проверьте:

```bash
git --version
```

Если появилась версия Git — всё готово. Если написано, что команда не найдена, попробуйте перезапустить VS Code после установки Git.

### Настройте имя для коммитов

Это делается **один раз на компьютере**:

```bash
git config --global user.name "Ваше имя или ник"
git config --global user.email "ваша-почта@example.com"
```

Git добавляет эти данные к вашим коммитам. Если не хотите показывать обычную почту в истории, используйте адрес GitHub `noreply` из настроек аккаунта.

## Что вообще делают Git и GitHub?

Представьте, что вы работаете над общим документом, но можете:
- сохранить понятную «контрольную точку» изменений — это **коммит**;
- работать над своей версией, не ломая общую — это **ветка**;
- отправить сделанное в общий репозиторий — это **push**;
- попросить команду посмотреть ваши изменения перед добавлением — это **Pull Request** (PR).

**Git** работает у вас на компьютере, **GitHub** хранит общую копию в интернете. `git clone` забирает проект к вам, `git push` отправляет ваши коммиты обратно.

## Первый проход: 10 шагов

Дальше команды можно копировать в терминал. Выполняйте их **по одной** и проверяйте результат.

### 1. Скачайте репозиторий

Откройте папку, в которой хотите хранить учебные проекты, и выполните:

```bash
git clone https://github.com/tishelka/git-training.git
cd git-training
```

**Важно:** кнопка GitHub «Download ZIP» здесь не подойдёт — в архиве не будет истории Git. Нужен именно `git clone`.

### 2. Убедитесь, что всё на месте

```bash
git status
git branch --show-current
```

Сначала вы должны оказаться в ветке **master**. Да, здесь она называется именно так.

### 3. Создайте свою ветку

Вместо `anna` напишите свой ник латиницей:

```bash
git switch -c practice/anna-profile
```

Ветка — ваше рабочее пространство. Общую `master` пока не трогаем.

### 4. Добавьте файл о себе

Откройте папку `students` в VS Code. Посмотрите на [пример анкеты](students/_example.md) и создайте **новый** файл — например, `students/anna.md`.

В нём напишите имя или ник, роль в команде, что хотите изучить и одно занятие, которое любите в свободное время. Личные контакты, телефон и другие приватные данные указывать не нужно.

Не редактируйте файл `_example.md` и не меняйте анкеты одногруппников.

### 5. Посмотрите, что изменилось

```bash
git status
git diff
```

Новый файл Git покажет в `git status`, а `git diff` обычно показывает изменения уже отслеживаемых файлов. Это нормально.

### 6. Добавьте файл в будущий коммит

```bash
git add students/anna.md
git status
```

`git add` — не отправка на GitHub! Вы всего лишь отметили, какие изменения попадут в ближайший коммит.

### 7. Сделайте коммит

```bash
git commit -m "Add Anna profile"
```

Коммит — сохранённая точка истории. Лучше писать сообщение о том, **что именно изменилось**, а не «правки» или «123».

### 8. Отправьте ветку на GitHub

```bash
git push -u origin practice/anna-profile
```

При первом push GitHub может попросить войти через браузер. **Пароль от GitHub в терминале как пароль для Git через HTTPS не используется.** Обычно авторизацию помогает пройти Git Credential Manager.

Если появилось `403` или `permission denied` — скорее всего, вас ещё не добавили в Collaborators либо вы не приняли приглашение. Напишите руководителю.

### 9. Создайте Pull Request

Откройте [репозиторий на GitHub](https://github.com/tishelka/git-training). После push обычно появляется кнопка **Compare & pull request**. Если её нет, откройте вкладку **Pull requests → New pull request**.

Выберите:
- **base:** `master` — куда предлагаем изменения;
- **compare:** `practice/anna-profile` — откуда берём изменения.

Название, например: **Add Anna profile**. Опишите, что сделали и что проверили, затем нажмите **Create pull request**.

Ваш PR проверит руководитель. Если он попросит что-то поправить, просто измените файл **в той же ветке**, сделайте ещё один коммит и `git push` — PR обновится сам.

### 10. После объединения PR обновите проект

Когда изменения попадут в `master`:

```bash
git switch master
git pull --ff-only origin master
```

Теперь у вас есть свежая общая версия. **Следующее задание начинайте в новой ветке**.

## Короткая шпаргалка на каждый день

```bash
git status                         # Что сейчас изменено?
git switch master                  # Перейти на общую ветку
git pull --ff-only origin master   # Забрать свежие изменения
git switch -c practice/my-task     # Начать новую задачу
git add path/to/file.md            # Подготовить свой файл
git commit -m "Describe change"    # Зафиксировать изменение
git push -u origin practice/my-task # Отправить новую ветку
```

**Чего пока не делаем:** не работаем напрямую в `master`, не используем `git push --force` и не запускаем `git reset --hard` по случайному совету из интернета. Если возникла проблема — сначала `git status`, затем спросите.

## Когда задание считается выполненным?

Не когда у вас появился коммит на компьютере, а когда **создан PR**, получены замечания (если они есть), изменения приняты и попали в `master`.

Выходить в интернет с личными данными не нужно: ник и учебные ответы вполне подойдут.

Удачи! Через несколько таких шагов Git перестанет казаться набором странных заклинаний 🙂
